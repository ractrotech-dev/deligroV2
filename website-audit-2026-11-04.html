Website audit, 4 November 2026

Deligro, run with the open-source Website Audit Toolkit against the local dev server (branch wip/welcome-landing), plus a latency check against production and the database. Public pages only: the tool cannot sign in, so admin, vendor and manager screens were measured through their data loaders instead.

Why the site is slow

FindingEvidenceStatus
Server code and database are on opposite sides of the worldDatabase: Supabase ap-northeast-1 (Tokyo). Production functions: Vercel iad1 (Washington DC), per x-vercel-id: bom1::iad1. Every query crosses the Pacific twice.Fixed vercel.json pins functions to hnd1 (Tokyo). Takes effect on the next deploy.
Admin loaders make several trips one after anotherFrom India to Tokyo: Orders list 1.5 s, Live board 1.5 s, Top shops 1.1 s, on a small database. Each is 3 to 4 sequential round trips.Mostly fixed by the region change; each trip drops to a few milliseconds.
Auto-refresh stacked requestsOrders refreshed every 4 s even while the previous refresh was still rendering.Fixed Skips a tick while one is in flight; Orders now every 10 s.
Users in India reach Tokyo, not MumbaiAbout 70 to 100 ms per page after the region change.Optional Moving the database to ap-south-1 needs a new project and a migration.
